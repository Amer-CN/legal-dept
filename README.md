## 📦 这是什么、里面有什么

**定位**：面向企业客户的**部门制中文法务 skill 套装**——不是孤立的单卡片工具，而是一条完整流程。

- **目标用户**：需要法务支持的企业（法务外包视角），尤其是没有专职法务团队的成长型企业。
- **硬约束**：纯文本 markdown，跨平台可移植，不依赖任何单一客户端的私有能力；不做量化风险打分，只做四级风险定级 + 判定理由。
- **定位说明**：这是法务部的**辅助工作流**，不是执业律师的替代品；对外正式出具法律意见、出庭、刑事辩护等仍须执业律师完成。
- **二期规划**：知产、公司治理、合规、独立前台岗、独立总监岗（首期复核职能由总纲代行）。

| 目录 | 是什么 | 装法 |
|---|---|---|
| `legal-dept/` | **部门总纲（唯一入口）**：接待 → 分诊 → 定级 → 路由 → 汇办 → 复核门 → 归档 | 必装 |
| `roles/` | 三个岗位：**合同法务岗 / 劳动用工岗 / 争议解决岗**（首期） | 必装；由总纲路由，也可显式直呼 |
| `shared/` | 全套装唯一的**风险标尺** + 4 份模板（意见书 / 审查意见 / 转介单 / 台账）+ 3 份红线与证据清单 | 必装；岗位按相对路径引用 |
| `industries/` | 行业包插槽规范（首期不挂载） | 可选 |
| `docs/` | 设计文档 + 触发实验记录 | 不用装，给维护人看 |

**为什么是部门制而不是一堆单卡片**：风险标尺全套装只有一把（`shared/risk-framework.md`），定级口径、复核门、台账留痕由总纲统一把关——活分给各岗位干，收口归总纲管，避免各岗位各说各话。

## ✨ 一件事进来怎么走

```
你说一件事 ── 部门总纲 legal-dept 接待（唯一入口）
   │
   ├─ 分诊定级：低 / 中 / 高 / 极高（唯一标尺，判定锚点见 shared/risk-framework.md）
   │
   ├─ 合同类事项 ────→ contract-counsel（合同法务岗）
   ├─ 劳动用工事项 ──→ employment-counsel（劳动用工岗）
   ├─ 争议解决事项 ──→ dispute-counsel（争议解决岗）
   │
   │        岗位承办 → 汇办 → 复核强制门（首期由总纲代行）→ 归档台账
   │
   └─ 能力圈外：刑事辩护 / 出庭代理 / 税务筹划 / 专业鉴定 / 异地执行
            ──→ 出具《案件转介单》，不硬答
```

**不想走分诊，直接点名也行。** 说 `legal-dept`、「用法务部」、「走法务流程」、「按法务部流程处理」进总纲；说 `contract-counsel` / `employment-counsel` / `dispute-counsel`，或中文「合同法务岗 / 劳动用工岗 / 争议解决岗」直接进岗位。独立调用岗位时，产出头部会自标「未经分诊」——显式降级，不静默。

## 🚦 风险标尺（全套装唯一）

只使用 **低 / 中 / 高 / 极高** 四级，判定锚点见 [`shared/risk-framework.md`](./shared/risk-framework.md)。

| 等级 | 办理方式 | 复核要求 | 归档 |
| --- | --- | --- | --- |
| 低 | 承办岗直接办理 | 承办岗自查，产出标注「本件为低风险，未过总监复核」 | 台账简记 |
| 中 | 承办岗办理 | 总纲自查（简复核），产出标注「已过简复核」 | 台账登记 |
| 高 | 承办岗办理 + 强制复核 | 总监复核；未复核则产出头部醒目标注「未经复核」 | 台账登记 + 交付物留存 |
| 极高 | 办理 + 强制复核 + 直报 | 总监复核，并同时出具升级建议（转人工律师 / 外部律所） | 台账登记 + 交付物留存 + 升级记录 |

> 首期总监复核职能由总纲代行。

三条铁律：

- 禁用一切 0-100 量化打分，禁用「风险指数」「安全评分」类表述。
- 禁用颜色词落盘（「绿/黄/红」仅为分诊口头语，落盘一律回写四级术语）。
- 定级必须写出「判定锚点编号 + 一句话事实」，禁止只写等级；不确定即向上取整。

## 📏 三条贯穿硬规则

1. **来源锁定**：引用法条写明法律名称 + 条文编号 + 关键原文；记忆来源标「待核实」并给出官方核验渠道。
2. **免责声明**：所有产出尾部固定携带「本文件由 AI 生成，不构成法律意见，不能替代执业律师的正式意见」。
3. **能力圈外转介**：刑事辩护、出庭代理、税务筹划、专业鉴定、异地执行等，出具《案件转介单》，不硬答。

## 🔌 挂载方式（跨平台）

本套装不依赖任何客户端私有机制，只需让宿主能读到这些 markdown 文件。按宿主能力选择：

| 你的宿主 | 挂法 |
| --- | --- |
| 支持目录式 skill | 把 `legal-dept/`、`roles/`、`shared/`、`industries/` 四个目录整体放入宿主的 skill / 规则 / 知识目录，宿主按 `SKILL.md` frontmatter 的 `name` 识别（`legal-dept`、`contract-counsel`、`employment-counsel`、`dispute-counsel`） |
| 只支持单文件规则 | 把 `legal-dept/SKILL.md` 整体粘贴为规则或系统提示；岗位 skill 按需追加粘贴，`shared/` 下的模板与清单按需以文件路径引用或一并粘贴 |
| 支持项目级知识库 | 把本仓库根目录挂为知识库 / 工作目录，让宿主按路径检索；此时所有 `shared/...` 相对路径引用可直接生效 |

### 命名冲突处理规则

- 本套装 name 统一加 `legal-` 前缀（总纲）或 `-counsel` 后缀（岗位），降低与用户既有 skill 重名的概率。
- 与用户既有 skill 重名时，以本套装目录路径为准，并在调用时显式写明路径（如 `roles/contract-counsel/SKILL.md`）。
- 如宿主按 name 唯一索引且无法区分，建议先卸载同名 skill，或将本套装目录整体改名后挂载（改名不影响内部引用，内部引用均为相对路径）。

## 🧭 维护与更新

- **责任人**：由挂载方指定（挂载时在总纲「更新归属」处填写责任人姓名或岗位）。责任人为空时，默认使用者本人负责。
- **复核周期**：至少每 6 个月复核一次法规相关内容与清单；监管规则发生重大变化时立即复核。
- **过期处理**：知识截至日期超 6 个月未复核，所有产出头部自动追加「知识可能过期，请复核」；未复核期间引用法条一律标「待核实」。
- **台账与留痕**：受理与办理记录见 [`shared/templates/intake-log.md`](./shared/templates/intake-log.md)；高与极高风险事项须留存交付物原文与复核意见。
