# 虚拟企业法务部 skill 套装设计文档

- 日期：2026-09-14
- 状态：已拍板（A/B/C 三席圆桌裁决，见 `.work/decisions/legal-dept-roundtable-verdict.md`）
- 范围：首期（总纲 + 合同/劳动/争议三岗 + 共享库 + 行业插槽规范）；二期补齐知产/治理/合规/前台独立岗/总监独立岗

## 1. 背景与目标

用户要一套服务企业客户的专业法务部 skill 体系：有部门架构、有成熟岗位 skill。现有大模型法律知识不成体系、易被用户带偏；CodeBuddy "专家团"是孤立卡片（无分诊、无复核、无协作）。GitHub 实测：ai-legal-claude（1731★，英美合同工具）、awesome-legal-skills（258 skill，中文 0 结果）、HHHHHejia 1251 skill（全美国法）、ChatLaw（7602★，2024-06 后实质停更）。**"中文法律 agent skill + 部门制组织"是真实空位**。

目标用户：企业客户（法务外包视角）；未来内置进"工程管家"项目做法务模块。因此硬约束：**纯文本 SKILL.md，跨平台可移植**，不依赖任何单一客户端私有能力。

## 2. 架构：A 部门制

```
Legal Dept/
├── legal-dept/SKILL.md        # 部门总纲（唯一入口）：接待→分诊→定级→路由→汇办
├── roles/
│   ├── contract-counsel/      # 首期：合同法务岗
│   ├── employment-counsel/    # 首期：劳动用工岗
│   ├── dispute-counsel/       # 首期：争议解决岗
│   ├── ip-counsel/            # 二期
│   ├── governance-counsel/    # 二期
│   ├── compliance-counsel/    # 二期
│   ├── legal-front-desk/      # 二期（首期其职能并入总纲；无总纲环境时为兜底入口）
│   └── legal-director/        # 二期（首期复核职能写进总纲"复核强制门"）
├── shared/
│   ├── risk-framework.md      # 四级风险等级 + 判定锚点
│   ├── templates/             # 法律意见书 / 审查意见书 / 案件转介单 / 受理记录台账
│   └── checklists/            # 合同红线 / 劳动红线 / 证据固定
├── industries/README.md       # 首期：只留行业包插槽规范，不填内容
└── README.md
```

路线："通用法务部主体 + 行业知识包插槽"（建工包二期或工程管家项目时挂载）。备选 B 流程制（无岗位概念，不符合需求）、C 单一大 skill（上下文爆炸）已否决。

## 3. 岗位 skill 统一骨架（Harvey 七段式中国化版）

分诊程序 → 本岗常见失败模式 → 法律框架（指针化：指向 shared 库 + 待核实标记，禁内联法条原文）→ 分析脚手架 → 交付物规范 → 升级条件 → 红线。允许按岗折叠留空，禁止注水。检验标准：3-variant 测试（换当事人/金额/管辖仍成立）+ framing-first（只写程序框架，不预埋个案答案）。

## 4. 三条贯穿硬规则

1. 来源锁定：引用法条须编号 + 关键原文；记忆来源标"待核实"。
2. 免责声明：所有产出物尾部固定携带"AI 生成，不构成法律意见"。
3. 能力圈外转介：刑辩/出庭/税筹等走《案件转介单》（案情摘要 + 已做工作 + 转介理由 + 律师选聘标准，含敏感信息最小化提示），不硬答。

## 5. 圆桌追加机制（C 席补强）

- 总监复核为总纲强制门：高/极高风险产出必过复核，否则醒目标注"未经复核"。
- 路由降级：总纲写显式调用路径；岗位可独立工作并自标"未经分诊"。首期前台岗未建，无总纲环境的兜底即为"岗位独立工作 + 自标未经分诊"（二期前台独立成岗后接管该兜底职责），此为对裁决条件(a)的首期替代实现，非静默降级。
- 法规真实性硬步骤：有检索能力的宿主引用法条前必须联网核验；无检索能力的宿主产出自动降级并声明"法条未经核验"。每个 skill 带知识截至日期戳 + 更新归属 + 过期预警（日期戳超 6 个月未复核，产出头部自动追加"知识可能过期"警示）。
- 总纲定义用户侧核实工作流（官方核验渠道指引）。
- 风险分级判定锚点写进 shared 库；禁用一切 0-100 量化分。
- 转介单模板含敏感信息最小化提示。

（注：上方第 5 节为圆桌评审补遗后的完整版；下文原重复段落已删除。）

## 5.1 风险标尺统一声明（圆桌评审补遗）

全套装只用一套风险标尺：低 / 中 / 高 / 极高（四级，判定锚点见 shared/risk-framework.md）。
"绿/黄/红"仅为分诊口语，不落盘：绿=低（常规办理）、黄=中（简复核后办理）、红=高或极高（总监复核门）。任何落盘文本、模板、标注一律使用四级术语，禁用颜色词；简报验收 grep 检查以四级词为准。

## 5.2 frontmatter 与触发词策略（圆桌评审补遗）

- 每个 SKILL.md 头部标准 frontmatter：`name`（kebab-case 全局唯一，如 legal-dept、contract-counsel）+ `description`（一句话职责 + 中文触发词，如"合同审查/起草/谈判"）。
- 总纲 description 声明"企业法务问题统一入口"，岗位 description 首句声明"由 legal-dept 总纲分派；亦可独立调用，独立调用时自标未经分诊"。
- 命名冲突预案：name 统一加 `legal-` / `-counsel` 前后缀；与用户既有 skill 重名时以本套装目录路径为准，README 记录重名处理规则。

## 6. 案件流转（总纲流程，全程使用四级术语，见 5.1）

受理（问清关键事实，防带偏第一闸）→ 分诊定级（低/中/高/极高）→ 路由派单 → 岗位承办（七段式）→ 汇办（总纲汇总多岗意见）→ 复核门（中级过简复核即总纲自查，高/极高过总监复核或标未经复核）→ 归档（台账）→ 升级/转介岔路（极高直报、能力圈外转介单）。

## 7. 验收（见 .work/current-task.md，5 条）

核心：可移植检查（无平台私有依赖）、来源锁定全覆盖、降级标注齐全、无量化分、触发实验记录落盘 docs/trigger-experiment.md（总纲分诊→岗位承办→复核标注链路实测走通或如实记录失败点）。

## 8. 反转条件（出现任一回炉）

实测触发不可靠且无显式调用手段→撤部门制并单个大 skill；用户只习惯单卡片→部门制过度设计；法规维护无归属人→维持 3 岗不扩编；工程管家内置法规检索→接地担忧解除可放宽；服务对象多为无外聘律师小微企业→复核门价值下降、8 岗砍半。
