# 外部评审简报：Legal Dept Skill 架构设计审查

> 用法：把本文件全文粘贴给外部 agent，附上仓库链接 `https://github.com/Amer-CN/legal-dept`（评审基线 commit `39abd04`）。要求它只评审、不改代码，输出评审报告。

---

## 1. 项目背景（给外部 agent 的上下文）

- 这是一套**中文企业虚拟法务部 Agent Skill 套装**，纯文本 Markdown，目标跨平台可移植（不绑定某一家 agent 客户端），未来要内置进“工程管家”项目做法务模块。
- 设计对标真实企业法务部：**部门总纲（唯一入口）→ 分诊定级 → 岗位承办 → 汇办 → 复核强制门 → 归档**，而不是孤立的单卡片工具。
- 当前编制：1 个总纲（`legal-dept`）+ 8 个岗位（合同 `contract-counsel`、劳动用工 `employment-counsel`、争议解决 `dispute-counsel`、知识产权 `ip-counsel`、公司治理 `governance-counsel`、合规 `compliance-counsel`、法务前台 `legal-front-desk`、法务总监 `legal-director`）+ `shared/`（风险框架、文书模板、核查清单）+ `industries/construction/`（建筑工程行业包 v1.0，首个行业包）。
- 已完成的内部决策（三席圆桌裁决，已拍板）：部门制（否决流程制/单一大 skill）、通用主体 + 行业插槽（不做建工专精）、禁用 0-100 量化打分、岗位统一七段式骨架、三条贯穿硬规则（见 §3）。

## 2. 评审范围

**审什么（架构设计）：**

1. 目录与职责划分：总纲 / 8 岗 / shared / industries 四层边界是否清晰，有无重叠或断层。
2. 分诊路由：总纲第 2–3 段的分诊、定级、路由表、显式调用路径、降级规则（无总纲/无岗位/无检索能力时）是否可执行、无歧义。
3. 触发词设计：总纲 `description` 约 180 个触发词与 8 岗触发词的覆盖关系、重叠词（劳动仲裁、保密协议、尽职调查、不正当竞争）的路由归属是否明确。
4. 风险标尺一致性：全套装是否只用低/中/高/极高四级 + `shared/risk-framework.md` 锚点 + 行业包 `I-1~I-7` 补充锚点，有无量化分、颜色词落盘。
5. 法规指针化：法律框架是否只放指针（名称 + 条文编号 + 关键原文要点 + 官方查询渠道 + 待核实标记），有无内联法条全文、有无编造条号之嫌。
6. 行业包插槽：`industries/README.md` 规范与 `construction` 首包的实现是否一致，包与主体的挂载关系是否成立。
7. 可移植性：有无依赖单一客户端私有能力的内容。

**不审什么：** 不逐条核验中国法条文的实体正确性（那是法条核验环节的事）；不改写任何文件；不评价商业价值。

## 3. 必须知道的三条硬规则（全套装适用）

1. 来源锁定：引用法条须写名称 + 条文编号 + 关键原文；记忆来源标「待核实」并给官方核验渠道。
2. 免责声明：所有产出尾部固定携带「AI 生成，不构成法律意见」。
3. 能力圈外转介：刑辩/出庭/税筹等走《案件转介单》，不硬答。

## 4. 必读文件（按顺序）

1. `README.md`（定位、目录、挂载方式、风险标尺、硬规则）
2. `legal-dept/SKILL.md`（总纲全流程，第 0–10 段）
3. `shared/risk-framework.md`（四级标尺 + E/H/M/L 锚点）
4. `roles/` 下 8 个 `SKILL.md`（重点看第 1 段分诊交接 + 第 3 段指针化 + 第 6 段升级条件）
5. `industries/README.md`（插槽规范）+ `industries/construction/SKILL.md` + `industries/construction/regulations.md` + `industries/construction/checklists/` 4 份清单
6. `docs/superpowers/specs/2026-09-14-legal-dept-design.md`（设计文档，含反转条件）
7. `docs/trigger-experiment.md` 第 6 节（二期复测：宿主加载实测结论与遗留事项）

## 5. 已知的诚实边界（评审时应考虑，不算新发现）

- 法条联网核验端到端未实测（无检索环境下降级声明已生效）；`gsxt.gov.cn` 曾返回 521。
- 自动触发（用户自然话术命中率）未实测；Skill 工具为显式调用机制。
- 总纲 description 约 180 触发词，截断风险已列为待观察项。
- 法规指针中优先受偿行使期限、签证索赔时限等细节标「待核实」，属有意为之（防编造），不应判为缺陷。

## 6. 要求输出的评审报告格式

1. 结论：通过 / 有条件通过（附必须修改项）/ 否决，一句话理由。
2. 逐项结论：按 §2 的 7 项逐条给通过/不通过 + 证据（文件 + 行号或节号）。
3. 问题清单：按 Critical（阻断：路由歧义、标尺打架、断链）/ Important（应改）/ Minor（建议）分级，每条给文件路径 + 行号 + 修改建议。
4. 越界与夹带检查：有无超出架构设计范围的内容、私有平台依赖、伪量化打分。
5. 把握程度：高/中/低 + 一句话依据。

## 7. 约束

- 只评审，不改任何文件，不输出改写后的全文。
- 引用条文编号时如无法确认现行有效性，请标「待核实」而不是断言。
- 报告控制在 1500 字以内。
