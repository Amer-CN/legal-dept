# 行业知识包插槽规范

- 版本：v1.0
- 知识截至日期：2026-09-14
- 更新归属：挂载方的法务部维护人（未指定时默认为使用者本人）
- 状态：插槽规范 v1.0；已挂载 construction v1.0（登记见根目录 README 第七节）

## 1. 为什么留插槽

通用法务部主体覆盖通用法律问题，但行业强监管事项（建工资质、招投标、医疗器械、金融牌照、数据出境等）依赖行业专门规定。这些内容时效腐化面大、地域差异大，未挂载的行业不预填，避免用过期内容误导用户。行业包按需挂载，挂载时按本规范执行。

## 2. 目录约定

```
industries/
├── README.md                 # 本规范
└── <industry-pack>/          # 行业包目录，kebab-case，如 construction、medical-device
    ├── SKILL.md              # 行业包入口（含 frontmatter，name 为 legal-industry-<pack>）
    ├── regulations.md        # 行业规定指针表（只放指针，不放全文）
    └── checklists/           # 行业红线清单
```

命名规则：行业包 name 统一加 `legal-industry-` 前缀，避免与用户既有 skill 重名。重名时以本套装目录路径为准（详见根目录 README 的重名处理规则）。

## 3. 行业包必须包含的内容

1. **frontmatter**：`name`（`legal-industry-<pack>`）+ `description`（一句话适用范围 + 中文触发词）。
2. **适用范围声明**：本包覆盖哪些行业事项、不覆盖哪些事项。
3. **行业规定指针表**：只写「法律/法规/规章名称 + 条文编号 + 关键原文要点 + 官方查询渠道」，禁止内联法条全文。
4. **行业红线清单**：可直接对照核对的检查项，逐项写「已覆盖 / 未覆盖 / 本件不涉及」。
5. **行业特有风险锚点**：如命中 `shared/risk-framework.md` 未覆盖的行业特有事由，在本包内补充锚点编号（前缀 `I-`，如 `I-1`），并在引用时写明「行业包补充锚点」。
6. **属地差异提示**：行业规定常为地方执行，必须列出需向哪个部门核实。
7. **知识截至日期 + 更新归属 + 过期预警**：与其他文件一致，超 6 个月未复核自动追加「知识可能过期，请复核」。

## 4. 行业包与主体的挂载关系

- 行业包不改变四级风险标尺，只补充判定锚点与检查项。
- 行业包不改变三条贯穿硬规则（来源锁定 / 免责声明 / 能力圈外转介）。
- 总纲分诊到岗位后，岗位按 `industries/<pack>/SKILL.md` 加载对应行业检查项；未挂载对应行业包时，岗位按「待核实」处理并提示用户向行业主管部门核实，不得凭印象断言行业规定。
- 行业包的产出物仍使用 `shared/templates/` 下的模板，头部固定项不减少。

## 5. 挂载与卸载

- 挂载：把行业包目录放入 `industries/`，并在根目录 README 的「已挂载行业包」清单登记（包名 + 版本 + 知识截至日期 + 责任人）。
- 卸载：从 `industries/` 移出目录并同步更新 README 登记；已在办的案件台账不受影响，但后续引用不得再依赖该包。
- 复核：行业包由登记的责任人负责，至少每 6 个月复核一次；行业监管规则发生重大变化时立即复核。

## 6. 已挂载状态

已挂载行业包见根目录 README 第七节登记（当前为 construction v1.0）。用户提出行业强监管事项时，岗位按「能力圈外或需专门核实」处理：能给出通用框架的给框架并标注「待核实」，需要行业专门资质或专门检索的，出具《案件转介单》（模板 `shared/templates/referral-form.md`）。
